Objetivo de la lección
Diseñar un sistema automático de vigilancia bibliográfica que filtre, clasifique y entregue nueva evidencia científica relevante directamente al clínico, sin que éste tenga que buscar activamente en bases de datos cada semana. Transformar la búsqueda reactiva en vigilancia proactiva.
📡 Analogía clínica
La vigilancia bibliográfica manual es como monitorizar los constantes vitales de un paciente mirando el monitor cada vez que te acuerdas — te pierdes los cambios entre visita y visita. El sistema de alertas automatizado es como la monitorización continua con alarmas configuradas: no tienes que mirar constantemente, pero cuando algo relevante cambia, el sistema te avisa en tiempo real. La diferencia no es solo de eficiencia — es de seguridad clínica.

El problema de la sobrecarga de información
PubMed publica aproximadamente 4.000 artículos nuevos cada día. Ningún clínico puede leer, ni siquiera escanear, ese volumen. El reto no es acceder a la información — es filtrarla relevantemente. La automatización con IA resuelve exactamente este problema: lee todo, entrega solo lo que importa para tu práctica clínica específica.
PubMed E-utilities API: búsqueda automatizada
PubMed ofrece una API gratuita (E-utilities) que permite realizar búsquedas programáticas, obtener abstracts y metadatos de artículos, y filtrar por fecha de publicación, tipo de estudio, idioma y docenas de parámetros más. No requiere registro ni pago.
API PubMed E-utilities — Endpoints principales: BASE URL: https://eutils.ncbi.nlm.nih.gov/entrez/eutils/ 1. BÚSQUEDA (esearch) — obtener IDs de artículos: GET /esearch.fcgi?db=pubmed&term=QUERY&retmax=20&sort=date&retmode=json Ejemplo — artículos de los últimos 7 días sobre insuficiencia cardíaca y nuevos tratamientos: term = "heart failure"[MeSH] AND "drug therapy"[MeSH] AND ("2024/01/01"[PDAT] : "3000"[PDAT]) 2. OBTENER DETALLES (efetch) — abstracts y metadatos: GET /efetch.fcgi?db=pubmed&id=ID1,ID2,ID3&rettype=abstract&retmode=xml 3. RESUMEN COMPACTO (esummary) — título, autores, fecha, revista: GET /esummary.fcgi?db=pubmed&id=ID1,ID2&retmode=json Parámetros clave de filtrado: - retmax: número máximo de resultados (hasta 10.000) - sort: "date" (más reciente primero) o "relevance" - datetype: "pdat" (fecha publicación) o "edat" (entrada en base de datos) - mindate/maxdate: rango de fechas (formato YYYY/MM/DD)
Anatomía de una búsqueda MeSH efectiva
MeSH (Medical Subject Headings) son los términos controlados de PubMed. Usarlos en lugar de texto libre garantiza que la búsqueda encuentra los artículos correctos aunque usen terminología distinta.
Prompt: construir query PubMed para vigilancia bibliográfica
Actúa como especialista en búsquedas bibliográficas biomédicas con experiencia en PubMed y vocabulario MeSH. Necesito crear una query PubMed para monitorizar semanalmente la nueva evidencia relevante para mi práctica clínica. Mi perfil clínico: - Especialidad: [ESPECIALIDAD] - Patologías principales que trato: [lista de patologías] - Aspectos específicos de interés: [tratamientos nuevos / diagnóstico / pronóstico / prevención] - Nivel de evidencia mínimo que me interesa: [ECA / revisiones sistemáticas / cualquier tipo] - Idiomas que puedo leer: [castellano, inglés, otros] Construye: 1. La query MeSH optimizada para PubMed (con operadores AND/OR/NOT y filtros de tipo de publicación) 2. Los filtros adicionales recomendados (fecha, idioma, tipo de estudio) 3. La URL completa de la API E-utilities para integrar en Make o Zapier 4. Una estimativa del número de artículos semanales que devolverá la búsqueda y si conviene ajustarla
Una query MeSH bien construida elimina el 90% del ruido bibliográfico. La diferencia entre "heart failure" como texto libre y "Heart Failure"[MeSH] puede ser de miles de artículos irrelevantes. Este prompt construye la query correcta para tu especialidad específica.
FLUJO: Vigilancia bibliográfica semanal en Make TRIGGER: Schedule — Cada lunes 6:00 AM PASO 1 — HTTP Request a PubMed esearch: → URL: https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi → Parámetros: db=pubmed, term=[TU_QUERY_MESH], retmax=50, sort=date, retmode=json → mindate = fecha de hace 7 días, maxdate = hoy → Resultado: lista de IDs de artículos nuevos PASO 2 — Filtro: ¿hay artículos nuevos? → Si count = 0: fin del flujo (sin email) → Si count > 0: continuar PASO 3 — HTTP Request a PubMed esummary (con lista de IDs): → Obtener: título, autores, revista, año, abstract → Resultado: JSON con metadatos de cada artículo PASO 4 — Iterator: procesar cada artículo → Para cada artículo: extraer título + abstract + URL PubMed + DOI PASO 5 — Agregador: construir lista formateada de artículos PASO 6 — HTTP Request a API Claude (filtrado por relevancia): → Enviar lista de títulos y abstracts → Prompt: "Eres revisor clínico de [especialidad]. De esta lista de artículos, identifica los 5 más relevantes para la práctica clínica. Para cada uno, resume en 2 frases la conclusión clínica principal. Descarta los básicos, epidemiológicos o de laboratorio sin aplicabilidad clínica directa." → Resultado: resumen ejecutivo de los 5 artículos más relevantes PASO 7 — Enviar email digest semanal: → Asunto: "📚 Bibliografía semanal [Especialidad] - semana [N], [año]" → Cuerpo: resumen Claude + lista completa con links a PubMed → Destinatarios: lista de distribución del servicio
Prompt: filtrar artículos PubMed por relevancia clínica
Eres un revisor clínico senior en [ESPECIALIDAD] con experiencia en medicina basada en evidencia. Se te proporciona una lista de artículos biomédicos publicados esta semana en PubMed. Tu tarea es actuar como filtro de relevancia clínica para un servicio hospitalario. CRITERIOS DE SELECCIÓN: - Prioriza: ensayos clínicos aleatorizados, metaanálisis, revisiones sistemáticas, guías clínicas actualizadas - Incluye si es muy relevante: estudios observacionales de gran tamaño con conclusiones prácticas - Descarta: estudios básicos in vitro, estudios en modelos animales sin traducción clínica inmediata, cartas al editor sin datos originales, artículos de epidemiología descriptiva sin impacto clínico directo LISTA DE ARTÍCULOS: [PEGAR AQUÍ: título, autores, revista, abstract de cada artículo] Para los 5 artículos más relevantes, proporciona: 1. Título original + URL PubMed 2. Conclusión clínica principal en 2 frases en castellano 3. Nivel de evidencia (1a / 1b / 2a / 2b / 3 / 4 / 5 según Oxford) 4. Aplicabilidad clínica inmediata: ALTA / MEDIA / BAJA + razón 5. Acción recomendada: "Revisar protocolo actual", "Información de contexto", "Potencial cambio de práctica", etc.
El filtro de IA elimina el tiempo de cribado manual. En lugar de leer 50 abstracts, el clínico recibe 5 artículos ya clasificados por relevancia práctica. La clave es el prompt específico de especialidad — un prompt genérico filtra peor que uno ajustado al perfil del servicio.
ClinicalTrials.gov y Cochrane: evidencia emergente y de máximo nivel
PubMed recoge lo ya publicado. ClinicalTrials.gov muestra los ensayos en marcha — evidencia que llegará dentro de meses o años. Cochrane proporciona síntesis de la evidencia de máxima calidad. Las tres fuentes juntas dan una visión completa del estado del conocimiento.
ClinicalTrials.gov API v2 (2023): BASE URL: https://clinicaltrials.gov/api/v2/studies BÚSQUEDA de ensayos en fase 3 sobre insuficiencia cardíaca: GET /studies?query.cond=heart+failure&filter.phase=PHASE3&filter.overallStatus=RECRUITING&pageSize=20 Campos útiles en la respuesta: - nctId: identificador único del ensayo (NCT...) - briefTitle: título breve - conditions: patologías estudiadas - interventions: tratamientos/intervenciones estudiadas - phase: fase del ensayo (1,2,3,4) - overallStatus: RECRUITING / COMPLETED / ACTIVE_NOT_RECRUITING - primaryCompletionDate: fecha estimada de finalización - enrollmentCount: número de pacientes objetivo USOS CLÍNICOS: → Monitorizar si hay un ensayo en marcha para un paciente concreto → Detectar cuando resultados esperados están próximos (completionDate) → Identificar centros participantes en España para derivación → Vigilar tratamientos emergentes que cambiarán las guías en 1-2 años
Prompt: analizar ensayos clínicos en marcha para tu especialidad
Analiza los siguientes ensayos clínicos activos en ClinicalTrials.gov para la especialidad de [ESPECIALIDAD]: [PEGAR AQUÍ: lista de ensayos con título, fase, patología, intervención, fecha estimada de finalización] Para cada ensayo, proporciona: 1. Resumen de la hipótesis que estudia (qué pregunta clínica responde) 2. Si la intervención es novedosa respecto al estándar actual 3. Fecha estimada de publicación de resultados 4. Potencial impacto en la práctica clínica actual si el resultado es positivo 5. Si hay centros participantes en España y cuáles Ordena los ensayos por potencial impacto clínico esperado (mayor a menor).
Cochrane Library RSS feeds
Cochrane publica RSS feeds por especialidad que pueden integrarse directamente en Make sin necesidad de API. Cada nueva revisión sistemática publicada dispara el flujo automáticamente.
URLs de feeds RSS de Cochrane por grupo (ejemplos): Cardiovascular: https://www.cochranelibrary.com/cdsr/doi/10.1002/14651858/rss Endocrinología: https://www.cochranelibrary.com/cdsr/feed?specialty=endocrine-and-metabolic Oncología: https://www.cochranelibrary.com/cdsr/feed?specialty=cancer En Make: → Módulo "RSS" → URL del feed Cochrane de tu especialidad → Trigger: "New item in feed" (se activa con cada nueva revisión publicada) → Acción: enviar email con título + abstract de la nueva revisión sistemática → Acción 2: guardar en Google Sheets "Biblioteca_Cochrane_Servicio"

Ministerio de Sanidad y sociedades científicas (SEMFYC, SEPAR, SEC, SEN, etc.) publican RSS de nuevas guías. Integrar estas alertas garantiza que el servicio conoce las guías nacionales en el momento de publicación, no meses después.

La EMA publica RSS de nuevos medicamentos aprobados, alertas de seguridad y cambios en fichas técnicas. Fundamental para farmacología clínica y seguridad del paciente. URL: https://www.ema.europa.eu/en/about-us/how-we-work/rss-feeds

NEJM / Lancet / BMJ eTOC
Las tres revistas de mayor impacto ofrecen eTOC (electronic Table of Contents) por email y RSS. Una alerta de nuevo número de NEJM o Lancet en Make puede filtrar automáticamente los artículos relevantes para tu especialidad usando IA.
Sistema integrado de vigilancia bibliográfica para un servicio
Combinar PubMed + ClinicalTrials + Cochrane + guías en un sistema unificado que entregue la evidencia correcta al profesional correcto en el formato correcto.
ARQUITECTURA: Sistema de vigilancia bibliográfica del Servicio de [Especialidad] FRECUENCIA Y FUENTES: → DIARIO (6:00 AM): alertas EMA + alertas de seguridad AEMPS → SEMANAL (lunes 7:00): PubMed (filtrado por IA) + ClinicalTrials novedades → MENSUAL (1er lunes): Cochrane nuevas revisiones + guías sociedades científicas DISTRIBUCIÓN DIFERENCIADA: → Todo el servicio: resumen ejecutivo semanal (5 artículos clave) → Residentes: adicionalmente el listado completo de nuevas publicaciones del mes → Jefe de servicio: también alertas ClinicalTrials con potencial impacto en cartera → Farmacia clínica: también alertas EMA y AEMPS diarias ESTRUCTURA DEL EMAIL SEMANAL: ──────────────────────────────── 📚 BOLETÍN BIBLIOGRÁFICO SEMANAL Servicio de [Especialidad] · Semana XX / 2025 ──────────────────────────────── 🔥 TOP 3 ARTÍCULOS DE LA SEMANA [Artículo 1]: Título · Conclusión en 2 frases · Nivel evidencia · Link [Artículo 2]: ... [Artículo 3]: ... ──────────────────────────────── 🧪 ENSAYOS EN MARCHA RELEVANTES [1 ensayo novo o con novedades esta semana] ──────────────────────────────── 📋 ARTÍCULOS COMPLETOS ESTA SEMANA (N artículos) [lista con título + link PubMed] ────────────────────────────────
Prompt: crear el boletín bibliográfico semanal del servicio
Eres el responsable de formación continuada del Servicio de [ESPECIALIDAD] de un hospital del SNS. Tienes los siguientes artículos publicados esta semana en PubMed relevantes para tu especialidad: [LISTA DE ARTÍCULOS: título, autores, revista, abstract] Genera el boletín bibliográfico semanal del servicio con este formato: ENCABEZADO: Servicio de [Especialidad] · Semana [N] de [año] SECCIÓN 1 - TOP 3 ARTÍCULOS: Para cada uno: título, revista, nivel de evidencia, conclusión clínica en 2 frases, y un apartado "¿Qué cambia en nuestra práctica?" con respuesta honesta (puede ser "nada aún" o "revisar protocolo X") SECCIÓN 2 - RADAR DE ENSAYOS CLÍNICOS: [Si se proporciona lista de ClinicalTrials] — 1-2 ensayos en fase 3 con potencial impacto SECCIÓN 3 - LISTADO COMPLETO: Todos los artículos con título + link PubMed Tono: profesional, conciso. El boletín debe leerse en menos de 5 minutos.
Este prompt convierte un conjunto de datos bibliográficos brutos en un boletín de lectura humana en 5 minutos. El valor añadido clave es la sección "¿Qué cambia en nuestra práctica?" — obliga al sistema a ser honesto sobre el impacto real de cada artículo, evitando sobreestimar la aplicabilidad inmediata de evidencia preliminar.
