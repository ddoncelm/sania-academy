Dashboards clínicos automatizados:
Power BI, Looker Studio y reporting de indicadores sin intervención manual
15-20 minutos
Nivel intermedio
Visualización de datos
0%
Objetivo de la lección
Diseñar dashboards clínicos que se actualicen automáticamente con datos del HIS o fuentes externas, aplicando principios de visualización efectiva para que los indicadores lleven a decisiones concretas — no solo a leer números.
📊 Analogía clínica
Un dashboard clínico mal diseñado es como una analítica completa con 80 parámetros entregada sin interpretar: hay mucha información pero ninguna conclusión. Un buen dashboard es como el informe de guardia del adjunto: selecciona los 5-8 indicadores que importan hoy, los presenta con contexto (normal / alerta / crítico) y apunta directamente a la acción necesaria. La cantidad de datos no es el objetivo — la claridad para actuar sí lo es.
Los 5 principios del dashboard clínico efectivo
🎯
1. Una pregunta, un dashboard
Cada dashboard debe responder a una pregunta específica: «¿Cómo van los tiempos de espera esta semana?», «¿Qué servicios tienen indicadores ACSA en rojo?», «¿Cuál es la ocupación de camas en tiempo real?». Un dashboard que intenta responder diez preguntas a la vez no responde bien ninguna.
🚦
2. Semáforo como lenguaje universal
Verde / ámbar / rojo es el sistema de alertas más rápido de procesar visualmente. En sanidad ya es el lenguaje del triaje. Úsalo en los dashboards: verde = dentro del estándar, ámbar = atención (5-15% de desviación), rojo = acción requerida (>15% de desviación o umbral crítico alcanzado).
📉
3. Tendencia antes que valor puntual
Un valor aislado de «demora media: 14 días» dice poco. «Demora media: 14 días (↑ desde 9 días hace 3 semanas)» dice mucho. Incluye siempre la tendencia temporal. Un indicador dentro del estándar pero empeorando rápidamente requiere atención aunque aún no haya cruzado el umbral.
🔢
4. Máximo 8 indicadores por vista
La memoria de trabajo humana procesa cómodamente 5±2 elementos simultáneos. Un dashboard con 30 KPIs obliga a hacer scroll y deja de ser un dashboard para convertirse en una tabla. Si necesitas más indicadores, organízalos en pestañas temáticas.
⚡
5. Acción directa desde el dato
Cada indicador en rojo debe llevar a una acción concreta, no solo a preocupación. En el diseño del dashboard, define previamente qué se hace cuando cada indicador entra en rojo. El dashboard puede incluso incluir un botón de «acción» que genera automáticamente la notificación o el informe de incidencia correspondiente.
Looker Studio (Google Data Studio): dashboards gratuitos con actualización automática
Looker Studio es la herramienta de Google para crear dashboards conectados a fuentes de datos que se actualizan automáticamente. Es gratuita, no requiere instalación, y se integra nativamente con Google Sheets — la combinación ideal para hospitales que ya usan Google Workspace.
✅
Ventajas para sanidad
Gratuito sin límite de usuarios. Actualización automática desde Google Sheets (cada 15 min). Compartición por link sin necesidad de cuenta. Compatible con BigQuery para grandes volúmenes.
⚠️
Consideraciones RGPD
Los datos pasan por servidores de Google. Para indicadores agregados/anonimizados (KPIs sin datos individuales) es seguro. No usar con datos de pacientes identificables sin DPA firmado con Google Workspace for Healthcare.
ARQUITECTURA: Dashboard de calidad con Looker Studio FUENTE DE DATOS: Google Sheets (actualización automática cada 15 min) → Hoja "KPIs_Semana": columnas Indicador, Valor, Estándar, Semáforo, Tendencia → Actualizada por flujo Make cada lunes 7:00 AM con datos del HIS LOOKER STUDIO: → Conectar a Google Sheets como fuente de datos → Crear página 1: "Vista Directiva" — 6 KPIs clave con semáforo grande → Crear página 2: "Detalle por Servicio" — tabla con todos los indicadores → Crear página 3: "Evolución temporal" — gráficos de tendencia 12 semanas COMPARTICIÓN: → Link público (sin login) para directivos — solo lectura → Link con edición para responsable de calidad → Embedded en intranet del hospital (iframe) ACTUALIZACIÓN: → Looker Studio refresca automáticamente desde Sheets → Sin intervención manual → dashboard siempre actualizado
Estructura de datos en Google Sheets para Looker Studio
El diseño de la hoja de Google Sheets determina lo que puedes visualizar en Looker Studio. Esta estructura estándar permite la mayoría de visualizaciones clínicas sin configuración adicional.
ESTRUCTURA HOJA "KPIs_Dashboard": Columna A: Fecha (DATE) — formato YYYY-MM-DD Columna B: Servicio (TEXT) — nombre del servicio Columna C: Indicador (TEXT) — nombre del KPI Columna D: Valor (NUMBER) — valor numérico del indicador Columna E: Estándar (NUMBER) — valor objetivo/umbral Columna F: Unidad (TEXT) — %, días, nº, etc. Columna G: Semáforo (TEXT) — "Verde" / "Ámbar" / "Rojo" Columna H: Desviación (NUMBER) — (Valor-Estándar)/Estándar*100 Columna I: Tendencia (TEXT) — "↑ Mejora" / "↓ Empeora" / "→ Estable" FÓRMULA SEMÁFORO (en Sheets): =IF(ABS(H2)<5,"Verde",IF(ABS(H2)<15,"Ámbar","Rojo")) En Looker Studio: → Crear campo calculado "Color_Semáforo": CASE WHEN Semáforo = "Verde" THEN "#4CAF50" WHEN Semáforo = "Ámbar" THEN "#FF9800" ELSE "#F44336" END
Prompt: diseñar la estructura del dashboard para tu servicio
Necesito diseñar un dashboard de calidad asistencial para el Servicio de [ESPECIALIDAD] de un hospital del SNS usando Looker Studio. Contexto: - Indicadores ACSA que monitorizamos: [lista de indicadores] - Audiencia principal del dashboard: [directivos / jefes de servicio / todo el servicio] - Frecuencia de actualización deseada: [diaria / semanal / mensual] - Fuente de datos actual: [Google Sheets / Excel / CSV exportado del HIS / API] Diseña: 1. La estructura de páginas del dashboard (máximo 3 páginas, qué va en cada una) 2. Los 6-8 KPIs más importantes para incluir en la vista principal con sus umbrales de semáforo 3. Los tipos de gráfico más adecuados para cada indicador (número grande, línea de tendencia, barra comparativa, gauge, tabla) 4. La estructura de datos en Google Sheets que necesito preparar 5. Un campo calculado de Looker Studio para colorear automáticamente según semáforo 6. Qué automatización en Make necesito para que los datos se actualicen solos
Este prompt genera el diseño completo del dashboard antes de tocar Looker Studio — evita el error más común de empezar a arrastrar gráficos sin un plan, que produce dashboards caóticos que nadie usa. El diseño en papel (o en texto) debe preceder siempre a la implementación.
Power BI en hospitales del SNS: la opción Microsoft
Los hospitales que ya tienen Microsoft 365 suelen tener acceso a Power BI Pro o Premium. Power BI ofrece mayor potencia que Looker Studio para datos complejos, integración nativa con SharePoint y Teams, y acuerdos marco con la AGE que simplifican el cumplimiento normativo.
🪟
Integración nativa con Microsoft 365
Power BI se publica directamente en Teams y SharePoint — el equipo accede al dashboard sin salir del entorno de trabajo habitual. Los informes pueden embeberse en páginas de SharePoint del hospital o enviarse como archivos PDF programados a las bandejas de Outlook de los directivos.
🛡️
Cumplimiento ENS y RGPD facilitado
Si el hospital tiene Microsoft 365 con el módulo Healthcare (o el acuerdo marco AGE correspondiente), los datos procesados en Power BI permanecen dentro del tenant de Microsoft del hospital — en los mismos servidores que ya almacenan el correo y los documentos. Esto simplifica enormemente el análisis RGPD respecto a herramientas externas.
🤖
Power BI + Copilot (Fabric)
Microsoft ha integrado capacidades de IA generativa (Copilot) en Power BI: el usuario puede hacer preguntas en lenguaje natural sobre los datos («¿Qué servicio tiene mayor tasa de reingresos este mes?») y el sistema responde con el gráfico correspondiente. Disponible en licencias Fabric/Premium.
Fuentes de datos compatibles con Power BI en entorno hospitalario
📊
SharePoint Lists y Excel en SharePoint
La fuente más directa para hospitales Microsoft. Los datos se mantienen en SharePoint (dentro del tenant del hospital) y Power BI se conecta directamente. La actualización puede ser hasta automática en tiempo real con DirectQuery.
🗄️
SQL Server / Azure SQL
Para hospitales con el HIS sobre SQL Server, Power BI puede conectarse directamente a la base de datos. Requiere que el DBA habilite el acceso de solo lectura y que los datos estén anonimizados/agregados a nivel de indicador (no registros individuales de pacientes).
🌐
API REST del HIS + Power Query
Power BI incluye Power Query, que puede conectarse a cualquier API REST. Si el HIS del hospital tiene API, Power BI puede extraer los indicadores directamente sin exportación manual. La actualización puede programarse cada hora, diariamente, o en tiempo real.
Alertas automáticas desde Power BI
Power BI Service permite configurar alertas que notifican automáticamente cuando un indicador supera un umbral. Sin necesidad de que nadie esté mirando el dashboard.
CONFIGURACIÓN DE ALERTA EN POWER BI: 1. Abre el informe publicado en Power BI Service 2. Haz clic en el valor del KPI (número grande o gauge) 3. Selecciona el icono de campana (🔔) → "Administrar alertas" 4. Define: Condición (es mayor que / es menor que) + Umbral + Frecuencia 5. Elige notificación: email / notificación push en Power BI Mobile EJEMPLO CLÍNICO: → KPI: Estancia media (días) → Alerta: "Cuando estancia media > 8.5 días" → Notificación: email a jefe_servicio@hospital.es + jefe_planta@hospital.es → Frecuencia: máximo 1 alerta/hora (evitar spam si el valor fluctúa) COMBINADO CON POWER AUTOMATE: → Power BI alerta → dispara Power Automate → Power Automate: genera informe de incidencia + notifica a Teams → Crea tarea en Planner para el responsable
KPIs clínicos esenciales y cómo automatizar su cálculo
Los indicadores que deben estar en cualquier dashboard hospitalario, cómo calcularlos automáticamente desde los datos del HIS, y los umbrales estándar del SNS.
INDICADORES ASISTENCIALES CLAVE: 1. ESTANCIA MEDIA Cálculo: suma(días_ingreso) / nº_altas Estándar SNS: varía por GRD — objetivo general <7 días en hospitalización Semáforo: Verde <7d, Ámbar 7-9d, Rojo >9d 2. TASA DE REINGRESOS A 30 DÍAS Cálculo: (altas_reingresadas_30d / total_altas) * 100 Estándar SNS: <10% Semáforo: Verde <8%, Ámbar 8-12%, Rojo >12% 3. DEMORA MEDIA EN LISTA DE ESPERA Cálculo: suma(días_espera) / nº_pacientes_lista Estándar: según servicio y Comunidad Autónoma Semáforo: Verde <30d, Ámbar 30-60d, Rojo >60d (consultas externas) 4. ÍNDICE DE OCUPACIÓN DE CAMAS Cálculo: (camas_ocupadas / camas_disponibles) * 100 Óptimo: 85-90% (por encima dificulta urgencias; por debajo, ineficiencia) Semáforo: Verde 80-90%, Ámbar 90-95%, Rojo >95% o <70% 5. TASA DE CANCELACIÓN DE CIRUGÍAS PROGRAMADAS Cálculo: (cancelaciones / programadas) * 100 Estándar: <5% Semáforo: Verde <3%, Ámbar 3-7%, Rojo >7%
INDICADORES DE SEGURIDAD DEL PACIENTE: 1. CAÍDAS CON DAÑO DURANTE EL INGRESO Cálculo: (caídas_con_lesión / estancias) * 1000 (por 1.000 estancias) Estándar: <1.5 por 1.000 estancias Semáforo: Verde <1.5, Ámbar 1.5-3, Rojo >3 2. ÚLCERAS POR PRESIÓN NOSOCOMIALES (grado III-IV) Cálculo: (UPP_nosocomiales / pacientes_riesgo) * 100 Estándar ACSA: <1.5% en pacientes de riesgo Semáforo: Verde <1%, Ámbar 1-2.5%, Rojo >2.5% 3. ERRORES DE MEDICACIÓN CON DAÑO Cálculo: (errores_con_daño / ingresos) * 1000 Estándar: <2 por 1.000 ingresos Semáforo: Verde <1.5, Ámbar 1.5-3, Rojo >3 4. BACTERIEMIA ASOCIADA A CATÉTER (BAC) Cálculo: (episodios_BAC / días_catéter) * 1000 Estándar: <1 por 1.000 días-catéter Semáforo: Verde <0.5, Ámbar 0.5-1.5, Rojo >1.5 5. MORTALIDAD INTRAHOSPITALARIA (ajustada por riesgo) Cálculo: (exitus / ingresos) * 100 — comparar con media nacional del GRD Semáforo: Verde ≤media+1σ, Ámbar media+1-2σ, Rojo >media+2σ
Prompt: crear fórmulas de cálculo automático de KPIs desde datos del HIS
Tengo una exportación semanal del HIS en formato CSV/Excel con las siguientes columnas: [LISTA DE COLUMNAS DISPONIBLES EN TU EXPORTACIÓN] Necesito calcular automáticamente estos indicadores para el dashboard de mi servicio: [LISTA DE INDICADORES QUE QUIERES MEDIR] Para cada indicador, proporciona: 1. La fórmula exacta en Google Sheets / Excel para calcularlo desde mis columnas disponibles 2. Los filtros necesarios (solo ingresos del servicio X, solo el período Y, excluir Z) 3. El umbral de semáforo estándar del SNS o ACSA y cómo implementarlo como fórmula condicional 4. Si algún indicador requiere datos que no están en mi exportación, indica exactamente qué columna adicional necesitaría pedir al HIS También genera: - La función de Google Sheets que calcule automáticamente la tendencia semanal (comparación con las últimas 4 semanas) - Una fórmula que determine automáticamente si la tendencia es "Mejora", "Estable" o "Empeora"
El 80% del tiempo en la implementación de dashboards se va en la preparación de los datos y las fórmulas de cálculo. Este prompt genera las fórmulas listas para copiar-pegar en Sheets, eliminando el trabajo manual de derivación matemática y reduciendo errores de cálculo.
Prompt: interpretar un dashboard con indicadores en rojo
Soy jefe del Servicio de [ESPECIALIDAD]. El dashboard de esta semana muestra los siguientes indicadores: [LISTA DE INDICADORES CON SUS VALORES ACTUALES Y TENDENCIA] Los siguientes indicadores están en rojo o con tendencia de empeora: [INDICADORES PROBLEMÁTICOS] Ayúdame a: 1. Identificar las causas más probables de cada desviación según la literatura hospitalaria 2. Proponer las 3-5 acciones de mejora más efectivas para cada indicador en rojo 3. Priorizar qué indicador abordar primero según el impacto en la seguridad del paciente 4. Sugerir qué datos adicionales necesitaría recoger para confirmar la hipótesis de la causa raíz 5. Redactar el análisis para presentar en la Comisión de Calidad
El dashboard sin interpretación es solo datos. Este prompt convierte los indicadores en rojo en un análisis de causa raíz y un plan de acción — el verdadero valor del monitoreo continuo. El análisis generado es el punto de partida para la reunión de calidad, no el informe final.
